# S0-2 结论报告：macOS 平台形态评估与去 Tauri 薄壳拍板（Issue #33，D5′）

- **当前状态**：**已闭环（决策变更 D5′，放弃 macOS Tauri 薄壳）**。2026-11-25 在真实 macOS（Apple Silicon）编译运行 Tauri v2 脚手架验证后，确认**不需要维护 macOS 专属 Tauri 薄壳**，双桌面（macOS + Omarchy）彻底统一为 **纯 `mynote` 单二进制（CLI + Daemon + 内嵌 HTML）**。
- 原型目录 `spikes/s0-2-macos-tauri-spike/` 已随决策同步删除，正式仓库不再引入 `shell-macos/`；结合 S0-3 iPhone 真机实测闭环，**`ADR-06（平台形态）` 正式升级为 `Accepted`**。

## 1. macOS 真机实测暴露的工程事实（2026-11-25，Apple Silicon / `rustc 1.100.0` / `tauri 2.12.7`）

在真实 macOS 上构建并运行 Tauri v2 薄壳后，实证得到以下一线事实：

1. **Scheme A（`WKWebView` 导航 `http://localhost:<port>` + `HttpOnly; SameSite=Strict` Cookie）可行但有额外 ACL 维护面**：
   - 实测 `GET /v1/local/auth/exchange?ticket=...` → `303 Set-Cookie` → `POST /v1/local/ping` 返回 `has_cookie=true` [已测]；
   - 但 Tauri 2.12 将 `http://localhost:<port>` 判定为 `remote origin`，必须额外维护 `build.rs` 的 `AppManifest::commands`、自动生成的 `permissions/autogenerated/*.toml`、`capabilities/*.json`（含 `remote.urls`）以及图标/打包/签名流程。
2. **引入独立 GUI 壳与单人维护复杂度预算（C1）失配**：
   - Tauri 薄壳仅为了在 macOS 内置一条系统全局热键，却拉进了 450+ 个 crate 依赖、独立 `.app` 打包、未公证 Gatekeeper（`xattr -dr com.apple.quarantine`）以及「Tauri `.app` vs Homebrew `mynote` CLI」双二进制签名与 Keychain ACL 隔离问题；
   - 本项目的核心形态本就是 **CLI + 本地 Daemon + 内嵌 HTML**，在 macOS 上可直接用浏览器固定标签页或 Chrome「安装为应用」/ Safari「添加到程序坞」打开 `http://localhost:<port>`，配合用户现有系统工具（Raycast / Hammerspoon / Karabiner）即可切窗，或直接通过 `mynote open` / `mynote add` 使用。

## 2. 拍板结论（D5′，取代原 D5）

| 决策项 | 最终结论（D5′） | 说明与取舍 |
| --- | --- | --- |
| **双桌面交付形态** | **macOS 与 Omarchy 100% 统一为纯 `mynote` 单二进制（CLI + Daemon + `rust-embed` 内嵌 HTML）** | 彻底移除 `shell-macos/` 与 Tauri v2 依赖；双桌面零平台分支，统一通过本地浏览器 / Web App 访问唯一入口 `http://localhost:<port>`。 |
| **Daemon 托管与单写入方** | macOS：`launchd` LaunchAgent（`~/Library/LaunchAgents/dev.mynote.daemon.plist` / `brew services`）；Omarchy：`systemd --user` | SQLite 严格维持单写入方（`daemon.lock` + `0600 daemon.sock`）；Daemon 未运行时 CLI 短事务直写 WAL。 |
| **Origin 与本地鉴权** | 唯一 `Host`：`localhost:<port>`；唯一 `Origin`：`http://localhost:<port>`；`mynote open` 用 10s 一次性 ticket 换 `HttpOnly; SameSite=Strict` Cookie | 删除原 Scheme B（`tauri://localhost` + CORS + Bearer）分支，本地鉴权面缩到最小。 |
| **macOS 全局唤出方式** | 不由 `my-note` 内置全局热键；交由外部系统工具（Chrome/Safari Web App + Raycast/Hammerspoon/Karabiner）或终端 `mynote open` / CLI | 明确接受「macOS 不内置全局热键」这一取舍，换取零 GUI 壳维护成本。 |
| **macOS Keychain 访问** | 全局只有**唯一一个 `mynote` 二进制**访问 Keychain，彻底消除跨二进制 ACL 冲突 | 诚实说明：无正式 Apple Developer 证书的 ad-hoc 签名下，每次 `brew upgrade` 重编覆盖同一 `mynote` 二进制后，macOS login Keychain 仍可能提示一次授权（点一次「始终允许」即可；后续如感不便可按需配置本地自签名证书）。 |

## 3. 后续演进注记（2026-11-28，D5″ / `v0.3.2`）

上述「淘汰 Tauri v2 壳（`shell-macos/`）与 Scheme B 鉴权、双桌面底层统一为单一 `mynote` 二进制」的拍板继续有效。2026-11-28 在评估 GPUI 与纯 Swift `WKWebView` 后，项目于 [`apps/macos/`](../../apps/macos/README.md) 落地了**零第三方依赖的纯 Swift 可选薄壳 `MyNote.app`**（`v0.3.2` 随 CI 与 Release 发布 `MyNote-aarch64-apple-darwin.zip`），在不破坏上述底线的前提下补回 macOS 原生菜单栏与全局热键：

- **0 第三方依赖 / 0 Rust crate 增量**：仅调用系统自带 `AppKit` / `WebKit` / `Carbon` / `CryptoKit`，`swiftc -O` 编译耗时 `2.0–2.5 s` `[已测]`，`.app` 包体 `364 KiB` / 压缩后 `140 KiB` `[已测]`；
- **不碰 Keychain、不改 `SEC-05` 鉴权**：`MyNote.app` 仅经 `0600 daemon.sock` 申请 `ping` 与 `open_ticket` 后由 `WKWebView` 访问唯一入口 `http://localhost:<port>`，`SMK` Keychain 读写仍由 `mynote` 单二进制独占；
- **原生体验实测 `[已测]`**：Carbon `RegisterEventHotKey` 默认 `⌃⌥Space`（零辅助功能权限），窗口隐显唤出 `5.1–7.9 ms`，`HttpOnly` Cookie、`isSecureContext`、`/v1/local/ws` 与严格 `localhost` 外链拦截均已在本地及 GitHub Actions `macos-latest` 自动化自检通过；因无 Apple Developer ID，首次下载仍需执行一次 `xattr -dr com.apple.quarantine /Applications/MyNote.app`。
